OAuth2 Provider

接入说明

本站是 OAuth2 授权服务器：第三方应用用授权码 + PKCE拿到访问令牌， 再用令牌读取用户资料。账号、登录会话与权限始终由站点持有——应用永远拿不到密码。

这是什么

三个角色，一条链路：

  • 站点（本页所在站点）是授权服务器，持有账号、会话与授权记录。
  • 你的应用是客户端，只持有 client_id 与（机密客户端的）client_secret。
  • 用户在自己的浏览器里登录本站，并在确认页上决定授予哪些权限。

链路是：应用把浏览器送到授权端点 → 用户登录并确认 → 浏览器带着 code 回到应用登记的回调地址 → 应用用 code 换访问令牌 → 应用拿令牌读用户资料。授权码只能使用一次、10 分钟内有效。

1 创建应用

登录后打开 设置 → OAuth 应用，点「新建应用」。管理员还可以在后台 「OAuth2 应用」里管理站内全部应用。创建完成后你会拿到：

  • client_id——公开标识，出现在授权请求里。
  • client_secret——机密客户端才有，只在创建或重置时显示一次；丢了只能重置。

回调地址的规则，写错会在授权时被直接拒绝（而且不会回跳）：

  • 必须是 https；本地开发允许 http://127.0.0.1 与 http://localhost。
  • 授权请求里的 redirect_uri 必须与登记值完全一致，不做前缀或通配匹配。
  • 可以登记多个回调地址，但每次请求只能带其中一个。

SPA、移动端与命令行工具属于公开客户端：它们没有安全的密钥存放位置，因此没有 client_secret，必须用 PKCE。机密客户端（有后端）也建议带 PKCE。

2 发起授权

把浏览器导航到授权端点，参数如下：

参数必填说明
client_id是创建应用时拿到的标识。
redirect_uri是必须与登记值完全一致，需 URL 编码。
response_type是固定 code。
scope否空格分隔；省略时回落到应用登记的权限范围。
state建议随机串，回调时原样带回；用它防 CSRF 与串联请求。
code_challenge公开客户端必填BASE64URL(SHA256(verifier))，无填充。
code_challenge_method同上固定 S256（plain 不接受）。
 
https://站点域名/api/oauth/authorize
  ?client_id=sfo_client_xxx
  &redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback
  &response_type=code
  &scope=profile%20email
  &state=RANDOM_STRING
  &code_challenge=BASE64URL_SHA256_OF_VERIFIER
  &code_challenge_method=S256

PKCE 的 verifier 与 challenge 用一条命令就能算出来（base64url、无填充，这是 RFC 7636 的要求）：

verifier=$(openssl rand -base64 48 | tr -d '=+/' | cut -c1-64)
challenge=$(printf %s "$verifier" | openssl dgst -sha256 -binary \
  | openssl base64 | tr '+/' '-_' | tr -d '=')

端点会按会话状态分流：未登录先跳站内登录页（登录后回到同一个授权请求）；需要确认时跳确认页； 之前勾过「记住这次授权」的直接回跳。成功时回调地址上会多出 code 与 state。

回调时务必先校验 state 与自己发出的值一致，再处理 code。 回调地址上出现 error 时没有 code，不要继续换取令牌。

3 换取令牌

令牌端点由站点的 CSRF 中间件保护（所有 /api/oauth/* 的 unsafe 方法都要求 double-submit 令牌）。服务端到服务端的调用要先握手一次拿到 csrf_ cookie： 

curl -c jar.txt https://站点域名/api/oauth/csrf
CSRF=$(awk '$6=="csrf_" {print $7}' jar.txt)

curl -b jar.txt -X POST https://站点域名/api/oauth/token \
  -H "Content-Type: application/json" \
  -H "X-Csrf-Token: $CSRF" \
  -H "Origin: https://站点域名" \
  -d '{
    "grant_type": "authorization_code",
    "client_id": "sfo_client_xxx",
    "client_secret": "sfos_xxx",
    "code": "sfoc_xxx",
    "redirect_uri": "https://app.example.com/callback",
    "code_verifier": "原始 verifier"
  }'

成功响应：

{
  "access_token": "sfoa_…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "sfor_…",
  "scope": "profile email"
}

公开客户端不带 client_secret，改为在请求体里带 code_verifier； 机密客户端两者都带。响应里出现 refresh_token 时，说明这次授权可以在过期后继续续期。

4 读取用户资料

访问令牌走 access_token 查询参数，不是 Authorization: Bearer ——插件路由会剥离凭据头，Bearer 到不了插件进程。

curl "https://站点域名/api/oauth/userinfo?access_token=sfoa_xxx"
{
  "sub": "7",
  "id": 7,
  "username": "alice",
  "displayName": "Alice",
  "status": "active",
  "createdAt": "2026-01-02T03:04:05.123456789Z",
  "updatedAt": "2026-02-03T04:05:06Z",
  "profileUrl": "https://站点域名/u/alice",
  "email": "alice@example.com",
  "emailVerified": true,
  "scope": "profile email avatar",
  "clientId": "sfo_client_xxx",
  "avatar": "data:image/svg+xml;base64,PHN2ZyB4bWxucz0i…"
}

字段与是否恒在：

字段出现条件说明
sub / id恒在用户 id 的字符串 / 数字两种形态，同值。
username / displayName恒在登录名与昵称（昵称为空时回落成登录名）。
status恒在active / disabled / banned。
scope / clientId恒在本次令牌的授权范围与客户端标识。
createdAt / updatedAt宿主给得出才在注册时间与资料更新时间（UTC，RFC 3339）。
profileUrl能解析站点地址才在站内公开主页。
email / emailVerified授予 email 且在授权时读到授权时读取一次并保存的快照。
avatar授予 avatar 时恒在绝对地址；没有上传头像时是按显示名生成的确定性 SVG 头像（data URL）。
groups授予 users.groups用户组标识数组。
topicCount / commentCount授予对应 scope公开内容计数。

条件字段缺席时整个键不出现，不会是空串或 null： 据此区分「没授权 / 宿主没给」与「值为空」。

5 刷新、撤销与内省

刷新令牌：把 grant_type 换成 refresh_token，其余字段按机密 / 公开客户端补齐。

{
  "grant_type": "refresh_token",
  "client_id": "sfo_client_xxx",
  "client_secret": "sfos_xxx",
  "refresh_token": "sfor_xxx"
}

刷新令牌每次使用都会轮换：响应里给新的 refresh_token，旧的立即失效。 刷新时申请的 scope 不能超出原始授权，否则得到 invalid_scope。

撤销令牌（RFC 7009）与内省（RFC 7662）都需要客户端认证：

# 撤销：幂等，重复撤销同样返回 200
{ "token": "sfor_xxx", "client_id": "sfo_client_xxx", "client_secret": "sfos_xxx" }

# 内省：返回 active 与令牌元数据
{ "token": "sfoa_xxx", "client_id": "sfo_client_xxx", "client_secret": "sfos_xxx" }

用户侧随时可以在 设置 → OAuth 应用 → 已授权 里撤销对某个应用的授权； 撤销后该应用的全部令牌立即失效，之后调用 userinfo 得到 invalid_token。

6 权限范围

scope 是空格分隔的清单，三层约束从内到外：

  • 应用登记范围：该应用可申请的权限。请求超出这份清单会被 invalid_scope 拒绝。
  • 缺省值：请求不带 scope 时，服务端用应用登记的范围作为默认值。
  • 站点清单：管理员配置的硬上限，只能收窄可选范围；profile 是身份基底，始终允许。

9 限制与注意事项

  • 访问令牌只能用 access_token 查询参数交付，Authorization: Bearer 不会被读取。
  • 所有 unsafe 方法（POST）都需要 CSRF double-submit：先 GET /api/oauth/csrf，再带 X-Csrf-Token 与 Origin。
  • 有效期由管理员在「OAuth2 设置」里控制，默认授权码 10 分钟、访问令牌 1 小时、刷新令牌 30 天；修改只影响新签发的令牌。
  • email 是授权时的一次性快照；用户在站点改了邮箱，应用要等下一次授权才会看到新值。
  • createdAt / updatedAt 依赖宿主稳定查询，profileUrl 依赖站点公开地址；拿不到时字段整体缺席，接口状态仍是 200。
  • 本站只实现授权码模式：不支持 client_credentials、隐式模式（implicit）与设备码。
  • 请把 client_secret 留在服务端。浏览器、移动端二进制与仓库里的密钥都等于公开。

本页的 scope、端点与错误码表由插件在运行时提供（GET /api/oauth/docs），随版本更新。
